# Amdahl、Gustafson 与 USL：三条扩展律其实是一条

> 「这个程序能扩到多少核」有两种问法，答错问法就会拿到差一个数量级的答案。本 demo 把三条扩展律写成可执行的式子，用断言钉死它们的**退化关系**：USL 在 `β = 0, γ = 1` 时**逐点等于** Amdahl；Amdahl 与 Gustafson 的差别不是谁对谁错，而是 `P` 这个符号在两式里**根本不是同一个东西**。

代码：`python/scaling.py`、`python/selfcheck_scaling.py`（231 条断言）、`python/main.py`、`go/`（同口径 Go 实现）。

## 一、两问两答

| | 问题 | 写法（P = 可并行比例） | 上限 |
| --- | --- | --- | --- |
| **Amdahl (1967)** | 同一道题，加核能快多少（**强扩展**） | `S = 1/[(1−P) + P/N]` | `1/(1−P)` |
| **Gustafson (1988)** | 同样时间，能算多大的题（**弱扩展**） | `S = N − (1−P)(N−1)` | 无 |

实跑（`P = 0.95`）：

```text
Amdahl 上限      : 20.0x
Gustafson N=1000 : 950.05x
```

hpc101 给出的例子被逐字复现：`P = 0.9, N = 100` 时 `S = 100 − 0.1×99 = 90.1`；Cornell 的三种等价写法 `N·F_p + F_s = N + (1−N)F_s = (N−1)F_p + 1` 在 `P ∈ {0.5,0.9,0.95,0.99}` × `N ∈ {1,2,10,100,1000}` 上逐点互证。

## 二、头号陷阱：同一个 P，两种含义

hpc101 把这条单独框起来警告，本 demo 也**在这里踩了一次**：

- Amdahl 里的 `P`：**固定问题**在单机上的可并行比例
- Gustafson 里的 `P`：**放大后的问题在并行机上**测得的可并行比例

写代码的直接后果是**展开式写错**：

```python
gustafson(0.9, 100)      # = 1 + 0.9*99        = 90.1   ✅
1 + P*(N-1)              # 与上式恒等                    ✅
P + N*(1-P)              # = 90 + 0.1 = 90.1? 不，= 90.1 只有在 P 是**串行比例**时才对
```

`gustafson_alt` 首版写成了 `P + N(1−P)`，自检在 12 个用例上立刻报错。正确关系是：**`S = 1 + P(N−1)`（P 为可并行比例）与 `S = f + N(1−f)`（f 为串行比例）给出同一个数**，两者差一个 `1−P` 的替换。现在两个口径的函数并存（`gustafson` / `gustafson_serial`），并用一条交叉断言把它们的等价性钉死。

## 三、USL 把 Amdahl 收进去了

Gunther 的定理：**`β = 0` 且 `γ = 1` 时 USL 退化为 Amdahl 定律**。代数上：

```text
USL(β=0,γ=1) : C(N) = N / (1 + α(N−1)) = N / (αN + 1 − α)
Amdahl       : S(N) = 1 / (f + (1−f)/N) = N / (fN + 1 − f)      ← 令 α = f，两式逐项相同
```

自检在 `f ∈ {0,0.01,0.05,0.1,0.25,0.5}` × `N ∈ {1,…,4096}` 上断言**逐点相等**（`1e-9`），并断言 USL 的 `1/α` 渐近线就是 Amdahl 的 `1/(1−P)` 天花板。实跑：

```text
N=2     Amdahl(f=0.1)=  1.8182  USL(α=0.1,β=0)=  1.8182
N=8     Amdahl(f=0.1)=  4.7059  USL(α=0.1,β=0)=  4.7059
N=64    Amdahl(f=0.1)=  8.7671  USL(α=0.1,β=0)=  8.7671
N=1024  Amdahl(f=0.1)=  9.9129  USL(α=0.1,β=0)=  9.9129
```

也就是说：**Amdahl 是 USL 在"没有一致性开销"时的特例**，Amdahl 的串行比例 `f` 就是 USL 的竞争系数 `α`。而 USL 多出来的 `β` 负责 Amdahl 完全看不到的现象——加机器加到某个点后**吞吐往下掉**。

## 四、加核为什么最终没用：串行占比

`P = 0.9` 时串行部分在 wallclock 中的占比：

| N | 1 | 4 | 16 | 64 | 256 | 1024 |
| --- | --- | --- | --- | --- | --- | --- |
| 串行占比 | 10% | 30.8% | 64% | 87.7% | 96.6% | 99.1% |

并行部分被切得再细，串行那一段的**绝对时长**没变，于是它在总时间里的份额一路涨到接近 100%。到 N=1024，即使 90% 的代码是并行的，**99% 的墙钟时间花在串行段**——继续加核只是在给串行段陪跑。

## 五、UVA 的量化结论：要撑到 100 进程，并行比例得接近 99%

| 并行比例 P | N=100 的加速比 | 效率 |
| --- | --- | --- |
| 0.99 | 50.25 | 50.3% |
| 0.95 | 16.81 | 16.8% |

反解同样被断言（`parallel_fraction_for` 代回原式必须得到目标加速比）：

| 目标（100 进程） | 需要的可并行比例 |
| --- | --- |
| 10× | 0.90909 |
| 50× | 0.98990 |
| 90× | 0.99888 |

**目标从 50× 提到 90×，要求的并行比例从 98.99% 抬到 99.89%**——最后这 0.9 个百分点通常不是"再优化一下"能拿到的，这就是为什么强扩展到百进程级别几乎总要换算法或换问题规模（转弱扩展）。

弱扩展下 `ε = S/N`，`p → ∞` 时 `ε → 1 − f`：断言在 `N = 10⁶` 上验证（`f ∈ {0.01,0.05,0.1,0.3}`）。所以**弱扩展的效率极限也只是 `1 − f`**，串行比例照样是天花板，只是它不再限制**加速比的绝对值**。

## 六、踩过的坑

- **`P + N(1−P)` 与 `1 + P(N−1)` 差一个 `1−P` 的替换**，写错时只在 `P ≠ 0.5` 的点上暴露；`P = 0.5` 时两式数值相同（`1 + 0.5(N−1) = 0.5 + 0.5N`），**单点测试查不出来**——本 demo 的 12 条失败全部来自 `P ∈ {0.9,0.95,0.99}`。
- **"USL 退化为 Amdahl"要用逐点断言而不是极限断言**：只看 `N → ∞` 时两边都趋于 `1/f`，会漏掉 `α` 与 `f` 摆错位置（例如把 `α` 当成可并行比例）的错误。
- **`amdahl_limit(1.0)` 是 `+Inf`**，写 `1/(1−P)` 时要么特判要么接受除零；本 demo 显式返回 `inf` 并断言。
- **效率断言的方向要看实验设计**：强扩展效率随 N 单调下降，弱扩展效率趋于常数——把两者混在一个循环里断言必然有一条挂。
