# M/M/c、Erlang C 与容量拐点

> 「一台变八台，延迟就该降到八分之一」——本 demo 用 Erlang C 把这句话拆开算：加机器真正买到的是**等待概率的下降**，而不是服务时间的下降；服务时间那一份 `1/μ` 永远买不掉。再往下走两步：M/G/1 告诉你**服务时间方差**要付多少钱，M/M/1/K 告诉你**队列有界**时「丢弃」这件事该怎么记账。

代码：`python/queuemodel.py`、`python/selfcheck_mmc.py`（153 条断言）、`python/main.py`、`go/`（同口径 Go 实现）。

## 一、Erlang B 与 Erlang C：一对兄弟

```text
Erlang B（阻塞概率，无队列）：  B(E,m) = (E^m/m!) / Σ_{i=0}^{m} E^i/i!
Erlang C（等待概率，无限队列）： P_w = [ (E^m/m!)·m/(m−E) ] / [ Σ_{i=0}^{m−1} E^i/i! + (E^m/m!)·m/(m−E) ]
```

`E = λ/μ` 是以 erlang 计的 **offered traffic**，`m` 是服务台数；两者都要求 `E < m`（即 `ρ < 1`），代码里直接抛异常。

B 有两种等价写法，维基给出了**工程上更稳的递推**（大 E 大 m 时阶乘会溢出）：

```text
B(E,0) = 1
B(E,j) = E·B(E,j−1) / (E·B(E,j−1) + j)
1/B(E,j) = 1 + (j/E)·(1/B(E,j−1))
```

自检里三种写法（闭式 / 正向递推 / 倒数递推）在 `E ∈ {0.5,1,2,5,10}` × `m ∈ {1,2,3,5,10}` 上逐点互证到 `1e-9`。

**B 与 C 的关系式**（自检里同样逐点互证）：

```text
C(E,m) = B(E,m) / (1 − ρ(1 − B(E,m))),    ρ = E/m
```

手算校验：`C(1,2) = 0.2/(1 − 0.5·0.8) = 0.2/0.6 = 1/3`。

## 二、M/M/c 的四个量

`ρ = λ/(cμ)`：

```text
π_0 = [ Σ_{k=0}^{c−1} (cρ)^k/k! + (cρ)^c/c! · 1/(1−ρ) ]^{−1}
Wq  = C(c, λ/μ) / (cμ − λ)          W = Wq + 1/μ
L   = λW                            Lq = λWq
```

三个必须记住的结构性事实（都是断言，不是叙述）：

1. **Little 定律在 M/M/c 上照旧精确成立**：`λW = L`、`λWq = Lq`（到 `1e-9`）。排队模型换了，守恒律没换。
2. **平均忙碌的服务台数就是 `E = λ/μ`**，并且 `L − Lq = E`。所以「加机器降 ρ」这件事，`L` 里的 `Lq` 那部分会被压下去，`E` 那部分一动不动。
3. **`c = 1` 必须精确退化成 M/M/1**：`C = ρ`、`L = ρ/(1−ρ)`、`W = 1/(μ−λ)`。这是检查 M/M/c 实现写对了没有的第一道关。

实跑（`λ=8, μ=5`，即 `E = 1.6 erlang`，逐台加机器）：

| c | ρ | C | Wq | W | L |
| --- | --- | --- | --- | --- | --- |
| 2 | 0.800 | 0.7111 | 355.56 ms | 555.56 ms | 4.444 |
| 3 | 0.533 | 0.2738 | 39.11 ms | 239.11 ms | 1.913 |
| 4 | 0.400 | 0.0907 | 7.56 ms | 207.56 ms | 1.660 |
| 8 | 0.200 | 0.0003 | 0.01 ms | 200.01 ms | 1.600 |

`W` 的下界是 `1/μ = 200 ms`，八台机器把等待压到几乎为零，也换不来低于 200 ms 的逗留时间——**加机器买的是等待，不是服务**。

## 三、一台快的 vs c 台慢的

同样总处理能力 `cμ`：

| c | c 台各 5/s 的 W | 1 台 c·5 /s 的 W |
| --- | --- | --- |
| 2 | 555.56 ms | 500.00 ms |
| 4 | 349.11 ms | 250.00 ms |
| 8 | 257.21 ms | 125.00 ms |

**单台快机永远更优**（均值意义上）。原因是多台时会出现「有服务台空闲、同时有人在排队」的错配——只要不是所有忙碌的服务台都被占满，能力就被浪费了。现实中仍然选多台，是因为单台做不到那个 μ、以及可用性；但**拿均值当理由说多台更快是错的**。

## 四、M/G/1：方差的价格

Pollaczek–Khinchine 只需要服务时间的**均值与方差**：

```text
Wq = (ρ + λμ·Var(S)) / (2(μ − λ))          W = Wq + 1/μ
L  = ρ + (ρ² + λ²Var(S)) / (2(1 − ρ))
```

| 服务时间分布 | Var(S) | Wq | W | L |
| --- | --- | --- | --- | --- |
| M/D/1（常数） | 0 | 0.500 ms | 1.500 ms | 0.750 |
| M/M/1（指数） | 1/μ² | 1.000 ms | 2.000 ms | 1.000 |
| 高方差 | 9/μ² | 5.000 ms | 6.000 ms | 3.000 |

两条硬断言：**指数服务的 P-K 结果必须等于 M/M/1**（这是"M/G/1 推广了 M/M/1"的验证），**`Var = 0` 时排队等待恰为 M/M/1 的一半**。同一 `ρ` 下把方差从 0 拉到 `9/μ²`，`Wq` 涨了 10 倍——**优化尾部延迟比优化均值更能降低排队**，因为均值只出现在 `ρ` 里，而方差单独占一项。

## 五、M/M/1/K：客满即丢弃

```text
π_0 = (1−ρ)/(1−ρ^{K+1})      （ρ = 1 时退化为 1/(K+1)）
λ_a = λ(1 − π_K)             # 有效到达率
吞吐量 = μ(1 − π_0)
```

关键守恒断言：**`λ_a` 必须等于 `μ(1 − π_0)`**。这两条路一个是「进来的减去被丢的」，一个是「忙着的时候在往外吐」，它们必须相等；不相等就说明模型或实现错了。

| K | p_block | λ_a | L | W |
| --- | --- | --- | --- | --- |
| 1 | 0.333333 | 333.333 | 0.3333 | 1.000 ms |
| 2 | 0.142857 | 428.571 | 0.5714 | 1.333 ms |
| 5 | 0.015873 | 492.063 | 0.9048 | 1.839 ms |
| 10 | 0.000489 | 499.756 | 0.9946 | 1.990 ms |
| 40 | ≈0 | 500.000 | 1.0000 | 2.000 ms |

`K → ∞` 收敛回 M/M/1（`L → 1.0`、`W → 2 ms`，断言到 `1e-6`）。**有界队列的全部设计含义就在这一列**：`K=1` 时丢掉 1/3 的流量，但活下来的请求 1 ms 就返回；`K=40` 时几乎不丢，但排队把 `W` 抬到 2 ms。**丢弃不是事故的副产品，它是一种可以被显式选择的语义**。

## 六、踩过的坑

- **Erlang C 的 `E` 与 `m` 不能跨过 `E = m`**：`m − E` 在分母上，越界会先算出负数再算出荒谬值。构造时校验比事后 debug 便宜。
- **状态概率归一化不能写 `(cρ)^k` 的直接幂**：`k` 取到几千时 Python 直接 `OverflowError`。递推比值在 `k ≥ c` 时恒为 `ρ`，改成 `π_k = π_{k−1}·ρ` 逐项累加即可。
- **「c 台慢的优于 1 台快的」是错觉**，只有均值口径下反过来；说"多台更好"时必须说明是哪一口径（本 demo 断言的是 `W`，结论是快机更优）。
- **`ρ = 1` 的 M/M/1/K 要单独处理**：等比和公式分子分母同时为 0，必须走 `π_0 = 1/(K+1)` 的分支，自检里专门有一条五态等概率的用例。
