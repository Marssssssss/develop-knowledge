# 03 应用安全与供应链

> 08-安全 的第三个子领域。已有 `01-Web安全`(攻面在**请求**)与 `02-网络安全`(攻面在**链路**),
> 本目录关注攻面在**构建与依赖**:代码本身、依赖树、CI 流水线、发布产物。

## 子目录规划

```
03-应用安全与供应链/
├── README.md
├── SAST与污点分析/        # 源码级数据流:source → sink,为什么误报率高
├── 依赖漏洞与SBOM/        # 传递依赖、版本区间匹配、SBOM 格式与产出时机
├── 供应链完整性/          # 制品签名、构建来源证明、可复现构建
├── 密钥管理/              # 硬编码凭据检测、密钥轮换、最小权限凭据下发
└── CI流水线加固/          # 权限最小化、不可信输入(PR 分支)、构建缓存投毒
```

## 与其它子领域的分工

| 子领域 | 攻面 | 典型问题 |
| --- | --- | --- |
| `01-Web安全` | 请求 | XSS / CSRF / SQL 注入 / 同源策略 |
| `02-网络安全` | 链路 | 传输机密性、中间人、协议指纹 |
| **应用安全与供应链** | **代码与制品** | 依赖漏洞、构建链投毒、制品不可溯源 |

三者的交叉点在于「攻击者能控制什么输入」:`01` 是可控的请求参数,`02` 是可控的网络包,
本目录是**可控的依赖版本与构建环境** —— 后者更隐蔽,因为攻击发生在你信任的环节之内。
