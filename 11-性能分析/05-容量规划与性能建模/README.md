# 容量规划与性能建模

> "压测跑出来 3000 QPS，那就按 3000 上线"——这是容量事故的标准开场。本子领域研究如何把**离散的测量点**变成**可外推的模型**，从而回答两个问题：**加机器还能不能线性扩张**、**在 SLO 破裂之前还剩多少余量**。
>
> 与 [03-基准测试方法论/](../03-基准测试方法论/) 的分工：那边保证"这个数字本身可信"，这里负责"用可信的数字做预测"。与 [04-全链路性能/](../04-全链路性能/) 的分工：那边是"已经慢了，拆开看"，这里是"还没慢，先算出来什么时候会慢"。

## 核心研究主题

- **Little 定律**：`L = λW`——不需要任何分布假设的普适守恒关系
- **排队论与拐点**：M/M/1 的 `W = S/(1−ρ)`、Kendall 记号与模型选择（M/M/1、M/M/c、M/G/1、M/M/1/K）
- **扩展性定律**：Amdahl（强扩展，天花板 `1/串行比`）vs Gustafson（弱扩展，线性）vs USL（含一致性开销，会出现**吞吐倒退**）
- **USL 参数拟合与峰值定位**：`Nmax = √[(1−α)/β]`、α 与 β 的相对大小如何区分"竞争瓶颈"和"一致性瓶颈"
- **余量论证**：为什么生产目标应落在峰值利用率 60%–70% 而非 90%+
- **过载处理**：限流位置（客户端限流 / 服务端自适应）、关键性（criticality）分级、降级优先级
- **池子尺寸**：线程池 / 连接池 / 并发度由 `L = λW` 反推，以及池子过小（排队）与过大（上下文切换）的两侧代价

## 原理详解

### 1. Little 定律：唯一真正必需的那条公式

**任意稳定系统**中，平均在系统内的项目数等于到达率乘以平均逗留时间：

```text
L = λ × W        L: 在系统内的平均数量(含排队)
                 λ: 到达率(请求/秒)
                 W: 平均逗留时间(秒)
```

它惊人的地方在于**不假设什么**：不假设到达分布、不假设服务时间分布、不假设排队规则。这就是它成为整个领域最实用结论的原因。

三个方向各用一次，量出两个、求第三个：

| 用法 | 已知 | 求 | 例子 |
| --- | --- | --- | --- |
| **定并发（sizing）** | λ = 500 rps，W = 200 ms | L = 100 | 需要能容纳 100 个并发请求的池子；给 90 就开始无界排队 |
| **找隐性等待** | L = 50，λ = 100 rps | W = 500 ms | 服务时间只有 50 ms → **450 ms 全在排队**；这段等待任何 profiler 都看不到，因为没有代码在跑 |
| **算吞吐上限** | 单 worker 一次处理一个，S = 10 ms | λ_max = 100/s | 每个 worker 上限就是 1/S，想更高只能加并发或并行 |

**第一个检查排队是否"已经是死队列"**：队列长度 10000、以 500/s 排空 → 队里每个元素要等 20 s。如果调用方 2 s 超时，**这 10000 个请求已经全部作废**——系统处于 100% 利用率、产出为零的状态，这正是有界队列存在的意义。

### 2. 拐点：延迟不是负载的函数，是"剩余余量"的函数

M/M/1（泊松到达、指数服务、单服务台）稳态下：

```text
ρ = λ / μ                     # 利用率,必须 ρ < 1 才稳定
W = S / (1 − ρ)               # 系统内平均时间,S = 服务时间
W_q = ρ / (μ(1 − ρ))          # 平均排队等待时间
L = ρ / (1 − ρ)               # 系统内平均数量
L_q = ρ² / (1 − ρ)            # 平均排队长度
```

把 ρ 代进去，形状立刻显形（S = 100 ms）：

| ρ | 倍率 | S=100 ms 时实际 W |
| --- | --- | --- |
| 10% | 1.1× | 111 ms |
| 50% | 2× | 200 ms |
| 70% | 3.3× | 333 ms |
| 80% | 5× | 500 ms |
| 90% | 10× | 1000 ms |
| 95% | 20× | 2000 ms |
| 99% | 100× | 10000 ms |

三条推论：

1. **70% → 80% 要多付 50% 延迟，90% → 95% 再翻一倍**。最后几个点的容量，用延迟计价时贵得离谱。
2. **流量图会撒谎**。流量在仪表盘上是线性的，延迟在利用率上是**双曲**的——"两周内流量 +12%，p99 翻 4 倍"完全符合模型，此时去找"哪个提交引入的回归"是找错了方向。
3. **ρ ≥ 1 就不稳定**（队列无界增长）。所以压在 100% 利用率上的系统不是"效率高"，是"已经在排队爆炸的临界点上"。

模型选择按 Kendall 记号 `A/S/c/K/N/Disc`：`M`=马尔可夫（泊松/指数）、`D`=确定、`G`=一般分布、`c`=服务台数、`K`=系统容量、`N`=呼叫群体。经验法则：**M/M/1 下一旦 ρ 超 0.8 就考虑改 M/M/c**（多台并行服务）；服务时间明显非指数（如常数或对数正态）时用 M/G/1，只需均值和方差（Pollaczek–Khinchine 公式）；物理上队列有上限（缓冲区、连接数）时用 M/M/1/K，此时"客满即拒绝/丢弃"本身就是一个必须显式设计的语义。

> **M/M/1 在细节上错、在形状上对**——你需要的是它的形状。

### 3. 三条扩展性定律：同一个程序为什么能算出两个不同的加速比

设 `N` 为处理器/节点数，`p` 为串行比例：

```text
Amdahl   (1967, 强扩展): S(N) = 1 / ( p + (1−p)/N )      极限 = 1/p
Gustafson(1988, 弱扩展): S(N) = p + N(1−p)   = N − p(N−1)  无上限,斜率 1−p
USL      (Gunther)     : C(N) = N / [ 1 + α(N−1) + βN(N−1) ]
```

- **Amdahl 回答"同一道题在 N 个核上快多少"**（问题规模固定 → **强扩展**）。串行部分设硬天花板：90% 可并行时上限 10×，与核数无关。计算科学里要在 100+ 进程上扩展，并行率必须逼近 99%。
- **Gustafson 回答"同样时间内能算多大的题"**（每核工作量固定 → **弱扩展**）。**没有上限**，随 N 线性增长，斜率就是并行比例。p = 0.05、N = 1000 时，Amdahl 说最多 20×，Gustafson 说 950×。
- **两条都对，只是问了不同的问题**——这是本主题**最经典的混淆点**。而且符号 `p` 在两式中含义不同：Amdahl 里 `p` 是**固定问题**在单机上的串行比例；Gustafson 里 `p` 是**扩大后的问题在并行机上**的串行比例。
- **深度学习站在 Gustafson 一边**：我们不是想把 MNIST 训快 1000 倍，而是想训大 1000 倍的模型。

### 4. USL：为什么加机器会越加越慢

USL 把"三 C"（Concurrency 并发 / Contention 竞争 / Coherency 一致性）合成一条曲线：

```text
C(N) = N / [ 1 + α(N−1) + βN(N−1) ]        # 相对容量 C(N) = X(N)/X(1)
X(N) = γN / [ 1 + α(N−1) + βN(N−1) ]       # 绝对吞吐,γ = 单个负载生成器的吞吐 = X(1)
Nmax = √[ (1 − α) / β ]                     # 峰值所在负载
Xmax = X(Nmax)
```

| 参数 | 名称 | 成因 |
| --- | --- | --- |
| **γ** (0 阶) | 并发 Concurrency | 理想并行度；α = β = 0 时退化为直线 `X(N) = γN` |
| **α** (1 阶) | 竞争 Contention | 共享资源的**排队/等待**代价（串行部分） |
| **β** (2 阶) | 一致性 Coherency | **分布式**资源之间**点对点数据交换**导致数据变为一致的延迟 |

四个区域：

| 情形 | 条件 | 现象 |
| --- | --- | --- |
| A 线性（等量获益） | α = 0, β = 0 | 完美并行直线 |
| B 共享资源代价 | α > 0, β = 0 | 次线性增长 |
| C 收益递减 | α ≫ 0, β = 0 | 渐近天花板 **1/α**，β = 0 时 **Nmax 在无穷远** |
| D **负回报（retrograde）** | α ≫ 0, β > 0 | 吞吐**随负载增加而下降** |

三个必须记住的点：

1. **`β = 0` 时 Nmax 在无穷远处**，曲线只是渐近到 `1/α`。只有 `β ≠ 0`（一致性代价非零）才存在**有限的峰值** `Nmax = √[(1−α)/β]`——**加机器加到某个点之后，吞吐真的会往下掉**，这就是 retrograde（倒退）。
2. **比较 α 与 β 的相对大小，就能判断糟糕的可扩展性来自竞争还是一致性**（此时该去减少锁竞争，还是该去减少节点间同步/分片重组）。
3. **`β = 0` 且 `γ = 1` 时 USL 退化为 Amdahl 定律**——Amdahl 被 USL **包含**了。USL 对应"多处理器线性负载相关 machine repairman 模型的同步排队上界"，与 Amdahl 同属有理函数族，两者都经过事件驱动仿真实验验证。

> 拟合哲学（原文强调）：用 USL 的**目的不是让曲线穿过每一个数据点**。它是用来外推趋势、定位峰值、并给出 α/β 这两个可干预的物理量的。

### 5. 从模型到余量：60–70% 这个数字从哪来

把第 2 节的表倒过来读就得到容量目标：

| 目标峰值利用率 | 平均等待倍数 | 评价 |
| --- | --- | --- |
| 50% | ≈ 1× 服务时间 | 响应良好 |
| 80% | ≈ 4× | 突发下已显慢 |
| 90% | ≈ 9× | 距级联失效只差两个事件 |
| 95% | ≈ 19× | 已经在告警 |
| 99% | ≈ 99× | 着火 |

所以**容量目标应落在峰值 60%–70% 利用率**。剩下的头寸不是"浪费"，它是三件事的缓冲：突发流量（λ 短时跳变）、单机故障（N 掉一个后剩余机器利用率立刻上抬）、以及慢查询/慢邻居带来的服务时间上移（S 变大）。按 90% 稳态利用率做规划，就会在每次大促发现 p99 翻倍。
