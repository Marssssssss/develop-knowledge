# 混合精度训练(FP16 / BF16 + loss scaling)

## 简介

混合精度训练把"权重、激活、梯度"存成 16 位,靠两件事保住精度:**FP32 主副本(master weights)** 承载参数更新,**loss scaling** 把梯度搬进 FP16 的可表示区间。它换来的是约 2× 的显存占用下降和 Tensor Core 上的大幅加速。

关键概念:

- **FP16 的窄指数**:最小正规数 `2^-14 ≈ 6.10e-05`,最小非正规数 `2^-24 ≈ 5.96e-08`(float32 是 `1.18e-38`)。小于 `2^-25` 的值直接**归零**。
- **master weights**:权重更新在 FP32 副本上累加,FP16 只作前向传播的输入。
- **loss scaling**:反向传播前把 loss 乘 `S`,所有梯度等比放大;`optimizer.step()` 之前再除回来。
- **动态缩放**:出现 `inf`/`nan` 就把 `S` 减半并跳过该步;连续若干步正常就把 `S` 翻倍。
- **FP32 累加**:Tensor Core 用 FP16 做乘法、FP32 做累加 —— 单元素是上千项乘积之和,在 FP16 里攒会爆掉精度。

## 原理详解

### 1. 两种 16 位格式

| 格式 | 符号/指数/尾数 | 最小正规数 | 最大有限值 | 相对精度 |
| --- | --- | --- | --- | --- |
| FP16 | 1 / 5 / 10 | 6.10352e-05(`2^-14`) | 65504 | `2^-11 ≈ 4.88e-04` |
| BF16 | 1 / 8 / 7 | 与 FP32 相同(`1.18e-38`) | 约 `3.4e38` | `2^-8 ≈ 3.9e-03`(舍入) |
| FP32 | 1 / 8 / 23 | 1.17549e-38(`2^-126`) | 3.40282e+38 | `2^-24` |

实测(NumPy 的真实硬件舍入):

```
fp16 最大相对误差 = 4.839754e-04   (理论 2^-11 = 4.882812e-04)
bf16 最大相对误差 = 7.749162e-03   (本实现是**截断**,上界 2^-7 = 7.8125e-03)
bf16(1e-30) = 9.984e-31           ← 保留指数范围
fp16(1e-30) = 0.0                 ← 直接归零
```

一句话选型:**要精度用 FP16,要范围用 BF16**。BF16 的指数位与 FP32 一样宽,所以几乎不会下溢;代价是尾数只有 7 位。

### 2. 下溢:F16 的"静默归零"

归一化层的反向、深层网络的小梯度,量级常常落在 `1e-8 ~ 1e-9`。这部分信息在 FP16 里**不是被近似,而是被删除**:

```
2^-30 = 9.313e-10  → fp16 0.000e+00   ← 已归零
...
2^-25 = 2.980e-08  → fp16 0.000e+00   ← 已归零(半个非正规步长以下)
2^-24 = 5.960e-08  → fp16 5.960e-08   ← 第一个可表示值
2^-23 = 1.192e-07  → fp16 1.192e-07
```

非正规区的步长恒为 `2^-24`,与指数无关 —— 所以**精度在非正规区是绝对值而非相对值**。

### 3. loss scaling

微分是线性的,所以 `∂(S·L)/∂w = S·∂L/∂w`:把 loss 乘以 `S`,链路里每个梯度都乘 `S`,不改变任何方向,只搬运数值区间。实测(2 万个对数均匀分布 `g ∈ [1e-9, 1e-2]` 的梯度):

| S | 被冲成 0 的比例 | 反缩放后最大相对误差 | 溢出 |
| --- | --- | --- | --- |
| 1 | **20.750%** | 1.000000e+00(信息全丢) | False |
| `2^10` | 0.000% | 2.848842e-02 | False |
| `2^18` | 0.000% | **4.864094e-04** | False |
| `2^20` | 0.000% | 4.864094e-04 | False |

两个读数很关键:

1. 不加缩放时 **20.75% 的梯度信息直接消失**(反缩放后相对误差 1.0 意味着该梯度变成 0,对应参数这一步完全不学)。
2. `S ≥ 2^18` 之后相对误差稳定在 `4.86e-04`,正好是 FP16 的 `2^-11` —— **精度在"全部落进正规数区间"时饱和,再放大 `S` 只是白吃溢出余量**。这就是动态缩放存在的意义:自动停在刚好够用的位置。

### 4. 为什么必须有 FP32 主副本

FP16 在 1.0 附近的间距(ulp)是 `2^-10 = 9.765625e-04`,而典型的学习率是 `1e-4 ~ 1e-7` 量级 —— 单步更新比 ulp **小 3~4 个数量级**,直接落在 FP16 里会"加了等于没加"。实测:

| 做法 | 1000 步 × 1e-7 | 20000 步 × 1e-7 |
| --- | --- | --- |
| 纯 FP16 权重 | `1.0`(**一动没动**) | `1.0`(仍然没动) |
| FP32 master | 0.999880791(下降 ≈1.2e-04) | 0.997615814,舍入回 FP16 = 0.99755859375 |

注意两点:① 20000 步时 FP32 主副本累计下降 2e-3,已经超过 ulp,所以连 FP16 副本都"看见"了变化;② FP32 累积 1000 步实测下降 `1.19e-04` 而解析值是 `1.00e-04` —— **FP32 自己也只有 2^-24 的相对精度**,1e-7 的步长在 1.0 附近属于亚 ulp 累积,这 1.9e-05 的偏差是 FP32 的累积误差,不是实现 bug。

### 5. 动态缩放算法

```
每步:
  step 前:  scaled_loss = loss * S;scaled_loss.backward()
  若梯度含 inf/nan:S ← S·backoff(通常 0.5),**跳过本步**,继续下一步
  否则:      g ← g / S(在 FP32 里做);optimizer.step()
            连续 growth_interval 步正常 → S ← S·growth(通常 2.0)
```

实测(200 步,`S₀=2^16`,growth=2,backoff=0.5,interval=10,人为在 step 50/120 注入溢出):

```
step  49: scale =   2097152.0
step  50: scale =   1048576.0   溢出 → 减半 + 跳过该步
step 119: scale =  67108864.0
step 120: scale =  33554432.0   溢出 → 减半 + 跳过该步
step 199: scale =  67108864.0   共 200 步,跳过 6 步
```

`S` 会一直涨到"刚好开始溢出"再回退 —— 这也是为什么缩放是 `2` 的幂:除/乘都是精确的指数位运算,不引入新的舍入。

### 6. 为什么要 FP32 累加

2000 个 `[0.5, 1.5)` 之间的数求和:

| 累加精度 | 结果 | 相对误差 |
| --- | --- | --- |
| FP64 参考 | 1997.840820 | — |
| FP16 逐项累加 | 2019.000000 | **1.059e-02** |
| FP32 逐项累加 | 1997.840820 | 0.000e+00 |

FP16 累加误差 1% —— 因为每加一次都要把当前和重新量化回 FP16,而和的量级(≈2000)远大于单项(≈1),量化步长按大数走。矩阵乘的一个输出元素是上千项之和,所以硬件必须用 FP32 累加。

## 对比 / 选型

| 方案 | 显存 | 速度 | 下溢风险 | 需要 loss scaling | 典型场景 |
| --- | --- | --- | --- | --- | --- |
| FP32 | 1× | 1× | 无 | 否 | 调试 / 小模型 |
| FP16 + AMP | ~0.5× | Tensor Core 大幅加速 | 高 | **是** | CNN / 早期 AMP 实践 |
| BF16 | ~0.5× | 同上 | 极低 | 通常仍需(防溢出) | 现代 LLM 训练主流 |
| FP16 纯推理 | ~0.5× | 高 | 视权重范围 | 否 | 部署 |

## 性能与边界

- 显存:权重/激活/梯度各减半,实测可用显存下降接近 2×(论文口径 "reduce the memory consumption by nearly 2x")。
- 速度:收益主要来自 Tensor Core(FP16 输入 + FP32 累加),而不只是"字节数减半"。
- 优化器状态(`m`、`v`)通常仍存 FP32 —— 大模型里这部分常常反过来成为显存瓶颈。
- 缩放因子是 `2` 的幂:乘除只动指数位,不引入舍入;`growth`/`backoff` 取 2 与 0.5 正因此。
- 边界:FP16 最大 65504,`S·max|g|` 超过它就在**该步**溢出,必须靠动态缩放兜住。

## 注意事项与常见坑

1. **反缩放要在 FP32 里做**:`np.float32(scaled)/S`;直接在 FP16 里除会把刚救回来的小梯度又量化一次。
2. **别把 `loss` 本身拿去打日志**:打印的是缩放后的值,量级看着正常其实是 `S` 倍;要打日志就先除回来。
3. **权重更新不能落在 FP16 上**(实测 20000 步纹丝不动):master weights 不是可选优化,是必需项。
4. **累加要在 FP32**:手写 kernel / 自定义算子时最容易犯的错。
5. **BF16 也不是完全不需要缩放**:它不会下溢,但会**溢出**;动态缩放通常仍开着。
6. **`inf` 会污染一切**:一旦发生溢出,该步的梯度必须整体丢弃(跳步),否则 `inf` 反传后权重变成 `nan`,整轮训练报废。
7. **`1e-30` 在 FP16 里是 0 而不是"很小"**:任何需要极宽动态范围的中间量(如未归一化的 logits、平方项)要么留在 FP32,要么先归一化。

## 参考资料(实际阅读过的权威来源)

- [Mixed Precision Training (Micikevicius et al., arXiv:1710.03740)](https://arxiv.org/abs/1710.03740) — 两条核心机制:①"maintaining a single-precision copy of the weights that accumulates the gradients after each optimizer step",②"scaling the loss appropriately to handle the loss of information with half-precision gradients";论文报告显存占用下降 near 2x,适用于 1 亿参数以上模型。
- IEEE-754 二进制 16 / 二进制 32 格式:FP16 = 1/5/10,最小正规数 `2^-14`、最小非正规数 `2^-24`、最大 65504;FP32 = 1/8/23,最小正规数 `2^-126`。本 demo 用 `np.finfo(np.float16/float32)` 直接读数核对。
