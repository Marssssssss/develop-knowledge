# Hough 变换直线检测(极坐标投票)

## 简介

- Hough 变换是一种**形状检测技术**:只要形状能写成数学形式(直线/圆/椭圆),即使在图像里**残缺或轻微变形**也能检出(OpenCV 官方教程原话)。
- 核心思想是**从图像空间到参数空间的投票**:图像空间中"一条直线上的 N 个点"这个全局共线检测难题,变成参数空间中"找一个 N 票的峰"这个局部极大值问题。
- 关键概念:
  - **极坐标表示** `ρ = x·cosθ + y·sinθ`:垂直线用 y=mx+b 表示时斜率无穷大,极坐标绕开该奇点
  - **累加器(accumulator)**:2D 数组,行=ρ(分辨率 1 像素)、列=θ(分辨率 1°),每格存票数
  - **对偶性**:图像空间一个点 ↔ 参数空间一条正弦曲线;参数空间一个峰 ↔ 图像空间一条直线
- 历史:Paul Hough 1962 年美国专利;Duda & Hart 1972 年引入极坐标参数化;概率 Hough 见 Matas & Galambos & Kittler 2000。

## 原理详解

```
图像空间(二值边缘图)            参数空间(累加器)

      y│  ●●●●●●  (y=6)         票数
      6│────────────            ┌──┐ ┌──────┐ ┌──┐
       │                        │  │ │ ████ │ │  │   θ=90°,ρ=6 处
       │                     ρ  │  │ │(峰值)│ │  │   12 票(线上 12 点)
       └──────────── x          └──┘ └──────┘ └──┘
                                  0°        90°    180°
   每个边缘点 (x,y):
     for θ in 0..179:  ρ = x·cosθ + y·sinθ  →  acc[round(ρ),θ] += 1
```

分步机制(OpenCV 教程 100x100 水平线例子):

1. 输入必须是**二值边缘图**——先做 Canny 或阈值化,再进 Hough。
2. 对每个边缘点,把 θ 从 0° 扫到 179°,逐个算出经过该点的直线参数 ρ,在累加器对应格子 **+1(投票)**。
3. 每个点在 θ-ρ 平面画出一条正弦曲线;一条真实直线上的所有点,曲线**交汇于同一格**——如教程例子中 (ρ=50, θ=90) 随点数从 1 票涨到最大票。
4. 在累加器里搜票数 ≥ threshold 的格子 → 每个峰给出一条直线 (ρ,θ)。
5. 累加器尺寸:θ 方向 180 列(1° 精度);ρ 方向最大距离 = **图像对角线长度**,故 ρ 行数取对角线像素数。

核心 API(OpenCV):

```
cv.HoughLines(image, rho, theta, threshold, srn=0, stn=0, min_theta, max_theta)
  image     8 位单通道二值图(函数可能就地修改)
  rho       ρ 分辨率(像素),常用 1
  theta     θ 分辨率(弧度),常用 CV_PI/180
  threshold 最少票数 → 即"认定为一条直线所需的最小共线点数"
  返回 (ρ,θ) 数组;ρ 像素、θ 弧度,原点为图像左上角
```

ρ 的符号约定(OpenCV):线在原点下方 → ρ>0 且 θ<180°;线在原点上方 → θ 仍取 <180° 但 ρ 为负;垂直线 θ=0°,水平线 θ=90°。本 demo 用 `ri = round(ρ) + 对角线长` 偏移,把负 ρ 也纳入累加器。

## 对比 / 选型

| 变体 | 思路 | 适用 |
| --- | --- | --- |
| 标准 Hough | 全点投票,输出无限长直线 (ρ,θ) | 需要直线方程本身的场合(车道线建模) |
| 概率 Hough(HoughLinesP) | 随机采样子集投票,直接输出**线段端点** | 工程默认;参数多 minLineLength / maxLineGap |
| 多尺度 Hough(srn/stn>0) | 粗累加器 + 细累加器两遍 | 对参数精度要求高时 |

## 关键代码片段

```python
for (x, y) in points:                    # 每个边缘点
    for t in range(180):                 # θ 1° 步进扫 [0°,180°)
        r = x*COS[t] + y*SIN[t]          # 经过该点的所有直线 = 一条正弦曲线
        acc[round(r) + rho_offset][t] += 1   # 投票
```

## 性能与边界

- 复杂度 O(P·Θ):P 个边缘点 × 180 个 θ。教程原文:"即使只有两个参数,计算量也很大"——概率 Hough 只采样子集即为此而生。
- 内存 O(D·Θ):D=2×对角线长。1000x1000 图、1° 分辨率 ≈ 2829×180 格。
- 精度瓶颈在分辨率:ρ 取 2 像素会把相距 1 像素的两条平行线并成一条;θ 取 2° 会把近水平线混叠。分辨率与算力直接此消彼长。

## 注意事项与常见坑

1. **进 Hough 前必须二值化**:直接对灰度图投票,每个像素都会贡献正弦曲线,累加器糊成一片。标准管线 Canny → HoughLines。
2. **threshold 的语义是"最少共线点数"**(demo 4):断线挖掉 4 个点后票数下降,阈值须相应调低;生产中它等价于最小直线长度。
3. **峰值不是单格**:量化误差让同一条直线的票散落在相邻 (ρ,θ) 格;必须做参数空间 NMS,否则一条线报成多条(本 demo ±2 邻域抑制)。
4. **θ 范围 [0°,180°) 而非 360°**:(ρ,θ) 与 (−ρ,θ+180°) 是同一条直线,半平面表示即可,但 ρ 必须允许负值(累加器行数 = 2×对角线+1)。
5. **图像 y 轴向下**:OpenCV 坐标系原点在左上角,推导 θ 时别按数学坐标系直觉硬套。
