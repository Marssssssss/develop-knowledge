# ML-KEM（FIPS 203，原 Kyber）原理级实现

## 1. 简介

ML-KEM 是 NIST 后量子标准（FIPS 203）选定的密钥封装机制，安全性建立在
**模格上的 Module-LWE 问题**上：给定 `A` 与 `t = A·s + e`（`s`、`e` 都是**小**噪声），
反推 `s` 被认为是困难的——即使对手有量子计算机。

本 demo 实现 ML-KEM-512，并逐层验证：模算术 → NTT → 环乘法 → 噪声采样 → 压缩 →
K-PKE → FO 变换。36 条断言全部实跑通过。

## 2. 参数（ML-KEM-512）

| 符号 | 值 | 含义 |
| --- | --- | --- |
| q | 3329 | 模数，2^12 < q < 2^13 |
| n | 256 | 多项式次数，环 R_q = Z_q[X]/(X^256+1) |
| k | 2 | 模块秩（ML-KEM-768 是 3，1024 是 4） |
| η₁ / η₂ | 3 / 2 | 密钥与密文的中心二项分布参数 |
| d_u / d_v | 10 / 4 | 密文两个分量的压缩位数 |

尺寸（FIPS 203）：封装密钥 `384·k + 32 = 800` 字节，密文 `32·d_u·k + 32·d_v = 768` 字节，
解封装密钥 1632 字节。自检里直接核对了这三个公式。

## 3. 为什么 NTT 是「不完全」的

教科书 NTT 需要 `2n` 次本原单位根，也就是 `2n | q-1`。这里：

```
q - 1 = 3328 = 256 × 13      ⇒ 256 | q-1，但 512 ∤ q-1
```

所以 `X^256 + 1` 在 Z_q 上**只能分解成 128 个二次不可约因子**，不能分解成 256 个一次因子。
Kyber 的做法：Cooley–Tukey 递归到 `len = 2` 就停下，最后一层用
`Z_q[X]/(X^2 - ζ)` 上的乘法（即 `basemul`）收尾。

```
r0 = a0·b0 + ζ·a1·b1
r1 = a0·b1 + a1·b0           （就是 (a0 + a1X)(b0 + b1X) mod X²-ζ）
```

代价：NTT 只有 7 层而不是 8 层；收益：乘法从 256² = 65536 次系数乘降到
128 次二次乘法 + 7 层蝶形。自检里有一条断言专门钉住
「basemul **不是**逐点相乘」这个常见误解。

### NTT 域自带一个 R = 2^16

参考实现全程用 Montgomery 乘法，于是：

```
invntt(ntt(a)) = a · R  mod q          R = 2^16
invntt(basemul(ntt(a), ntt(b))) = a · b        （R 被 basemul 吸收掉）
```

两条都在自检里断言过。**推论：噪声必须在正常域里加**，不能 `ntt(e)` 之后加进 NTT 域
再 `invntt`——那样得到的是 `e·R` 而不是 `e`，解密立刻崩。
（这是本 demo 调试时踩到的第二个坑，第一个是 ZETAS 抄漏一项。）

## 4. 三条容易写错的地方

| 位置 | 正确做法 | 写错的后果 |
| --- | --- | --- |
| 蝶形块步进 | 一个块跨 `2·len` 个系数，`start += 2·len` | 参考实现写成 `start = j + len`（C 里 j 出循环时已等于 start+len）；照抄到 Python 会因为 j 停在 `start+len-1` 而错位一格 |
| 噪声相加 | `t = invntt(Â·ŝ) + e`，`e` 在正常域 | 得到 `e·R`，解密失败且不报错 |
| 矩阵转置 | `u = Aᵀ·r + e₁`，`v = tᵀ·r + e₂ + ⌈q/2⌋·m` | 解不回明文 |

第三条为什么必须用转置：解密算的是 `v − sᵀ·u`，展开后
`(As+e)ᵀr + e₂ + m − sᵀ(Aᵀr + e₁) = m + (eᵀr + e₂ − sᵀe₁)`。
如果 `u` 用了 `A` 而不是 `Aᵀ`，中间那两项**不会相消**，剩下的就不是小噪声了。

## 5. 压缩：把解密错误率压到 2^-139 的代价

```
Compress_d(x)   = round(2^d / q · x) mod 2^d
Decompress_d(y) = round(q / 2^d · y)
```

`Compress` 是**有损**的（自检断言它不是双射），所以解密端拿到的 `u`、`v` 都带量化误差。
误差上界是 `⌈q / 2^{d+1}⌉`：

| d | 理论 ⌈q/2^{d+1}⌉ | 实测最大误差 |
| --- | --- | --- |
| 10（u） | 2 | 2 |
| 4（v） | 105 | 104 |

v 用更小的 d（更狠的压缩）换取更短密文，代价是 v 的误差更大——
参数就是这么权衡出来的：只要 `eᵀr + e₂ − sᵀe₁ + 量化误差` 不超过 `⌊q/4⌋`，
`⌈q/2⌋` 编码的每一位都能被正确判决。

## 6. FO 变换：从 CPA 到 CCA

K-PKE 本身只是 IND-CPA 安全的。ML-KEM 用 Fujisaki–Okamoto 变换把它抬到 IND-CCA：

```
封装：m ←$ ；(K̄, r) = G(m ‖ H(ek)) ；c = Enc(ek, m, r)
解封：m' = Dec(dk, c)
      (K̄', r') = G(m' ‖ H(ek))
      c' = Enc(ek, m', r')
      if c ≠ c':  K̄' = J(z ‖ c)        ← 隐式拒绝
      return K̄'
```

关键是最后那步**重加密比对**：解封装方会重新执行一次加密，确认密文是「诚实生成的」。
若不一致，不返回错误、不抛异常，而是返回一个**由 z 和密文导出的伪随机密钥**。
这样攻击者就得不到「这次解密是否成功」的侧信道——这是 FO 变换的精髓，
也是自检里三条断言（密钥不同 / 结果确定性 / 长度恒为 32）要钉住的语义。

## 7. 本 demo 的简化

- **不做字节打包/解包**：密文以「压缩后的多项式列表」在内存中传递，
  `ct_bytes()` 只用来做规范化比较。真实实现的位打包（10 位系数塞进 10 位）是纯机械工作，
  不影响任何密码学性质。
- **SHAKE 用标准库**：本仓库 `哈希/SHA-3-Keccak/` 已从零实现过 Keccak-f[1600]，
  这里不再重复一份（同一概念多份实现是 bug 温床）。FIPS 203 的 XOF/PRF/H/G/J
  全部建在 SHAKE128/256 之上。
- **朴素实现**：点乘不用 NTT 之外的优化，不做侧信道防护，**不可用于生产**。

## 9. 关键代码

环乘法（R 在这里被吸收）：

```python
def poly_mul(a, b):
    return invntt(basemul(ntt(a), ntt(b)))
```

basemul 的一个二次因子：

```python
out[i+s]     = (fqmul(a0, b0) + fqmul(fqmul(a1, b1), zz)) % Q
out[i+s + 1] = (fqmul(a0, b1) + fqmul(a1, b0)) % Q
```

CBD 采样（η=2，把 4 字节拆成 8 组、每组 4 比特两两相减）：

```python
d  = t & 0x55555555
d += (t >> 1) & 0x55555555
out.append(((d >> (4*j + 0)) & 0x3) - ((d >> (4*j + 2)) & 0x3))
```

## 10. 性能与边界

- 一次 K-PKE 加密要做 `k² + k = 6` 次 basemul 与 `k+1 = 3` 次 invntt（k=2）。
  矩阵 `A` 每次都从 `rho` 重新展开（不缓存），这是参考实现的做法，
  用 6 次 SHAKE128 换掉存 800 字节公钥之外的内存。
- 拒绝采样：每个 `A_ij` 平均需要 `256·(q/2^12)⁻¹ ≈ 1.23` 倍的输出字节。
- 解密失败率：ML-KEM-512 约 2^-139，不是零——这是格密码与 RSA/ECC 的根本区别之一，
  实现必须接受「理论上存在极小概率解不出」。
- 常量时间：真实实现必须保证 CBD 采样、拒绝采样、比较都是常量时间；
  本 demo 里的 Python 整数运算与 `list` 比较**不是**常量时间。

## 11. 注意事项与常见坑

1. **把 NTT 当逐点乘法**：`basemul` 是二次因子上的乘法，只对每 4 个系数成组。
2. **噪声加在 NTT 域里**：得到 `e·R`，解密静默失败。
3. **忘掉矩阵转置**：`u = Aᵀ·r` 而非 `A·r`，噪声不抵消。
4. **ZETAS 抄表错位**：实测抄漏一项会让 NTT 往返差一个非标量因子，且**不报错**。
5. **把 Compress 当无损**：它是有损量化，解密错误率的唯一来源。
6. **解封装失败时返回错误**：等于给攻击者一个解密预言机，FO 的隐式拒绝就白做了。
7. **复用 `r`**：同一个 `(m, r)` 会产出相同密文（自检断言了确定性），
   所以 `r` 必须由 `G(m ‖ H(ek))` 派生且绝不复用。
