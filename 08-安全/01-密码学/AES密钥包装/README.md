# AES 密钥包装：RFC 3394（AES-KW）与 RFC 5649（AES-KWP）

用「从零实现的 AES」把密钥包装算法完整跑通：AES-KW 是 6n 步 Feistel，
AES-KWP 只把初始值换成 `A65959A6 ‖ MLI` 并补上三条完整性检查。

```
python/main.py              # 演示（AES → KW → KWP → AIV 检查 → 边界）
python/selfcheck_kw.py      # 3973 条断言，实跑全绿
python/aes_core.py          # FIPS 197 AES-128/192/256
python/kw.py                # RFC 3394 + RFC 5649
go/                         # 同构 Go 移植（无工具链，四项静态检查全 OK）
```

## 1. RFC 3394：6n 步 Feistel

### 1.1 索引式表述（RFC 3394 §2.2.1 第二版，原文 line 236-257）

```
A = IV;  R[i] = P[i]
for j in 0..5:
    for i in 1..n:
        B    = AES(K, A | R[i])
        A    = MSB(64, B) ^ t          # t = n*j + i
        R[i] = LSB(64, B)
C[0] = A;  C[i] = R[i]
```

`s = 6n`，`n` 是明文 64 位块数。默认 IV（§2.2.3.1 line 362）：

```
A[0] = IV = A6A6A6A6A6A6A6A6
```

解包（§2.2.2）就是逐行求逆，**j 从 5 到 0、i 从 n 到 1**，
且用来拼 AES 输入的是 `A ^ t`（不是 `A`）：

```
B    = AES-1(K, (A ^ t) | R[i])
A    = MSB(64, B)
R[i] = LSB(64, B)
```

最后判 `A == IV`，不等就报错。

### 1.2 两种表述必须对拍

§2.2.1 其实给了两套写法：寄存器移位式（先给出）和索引式（"更易于软件实现"）。
区别在 `R` 怎么动：

| | 移位式 | 索引式 |
|---|---|---|
| 加密的块 | `A[t-1] | R[t-1][1]`（永远拿 1 号） | `A | R[i]`（跟着 i 走） |
| R 的更新 | `R[t][i] = R[t-1][i+1]`，`R[t][n] = LSB(B)` | `R[i] = LSB(B)`，原地 |

自检里 `ref_wrap_shift` / `ref_unwrap_shift` 实现了移位式，
与 `aes_wrap` / `aes_unwrap` 在六组向量上逐一比对——两套表述结果一致。

**这正是抽取向量时踩的坑**：RFC §4 的逐步表格是**索引式**，
第 k 步（`k` 从 1 起）加密的是 `A | R[i]`，其中 `i = ((k-1) mod n) + 1`。
我第一版按「永远是 `A | R[1]`」抽取，结果 96 组里恰好**偶数步全对、奇数步全错**
——因为 n=2 时奇数步才是 `i=1`。错得非常整齐，很容易误以为"实现基本对了"。

### 1.3 n 的下界

RFC 3394 §2.2（line 116-125）只要求 `n` 至少为 2：
"For key data with length less than or equal to 64 bits, … making this key wrap unnecessary."
所以 **AES-KW 包不了 8 字节**——那正是 RFC 5649 要补的洞。

## 2. RFC 5649：换 IV + 三条检查

### 2.1 AIV（`A65959A6 ‖ MLI`）

RFC 5649 §3（line 119-156）：高 32 位是常量 `A65959A6`，
低 32 位是大端无符号数 MLI（明文**字节数**，不是补齐后的长度）。
常量特意选得和 RFC 3394 默认 IV 的高 32 位（`A6A6A6A6`）不同，避免歧义。

补齐：右补最少的 `0x00` 使长度为 8 的倍数。§4.1 line 179：
`n = CEILING(m/8)`。**m 恰为 8 的倍数时不补**，但仍要走 AIV 分支。

n == 1 时**不走 6n 步 Feistel**，而是单个 ECB 块（§4.1 line 205）：

```
C[0] | C[1] = ENC(K, A | P[1])
```

§6 第二组向量（7 字节 → 16 字节密文）就走这条路。

### 2.2 三条完整性检查（§3 line 141-156）

```
1) MSB(32, A) == A65959A6
2) 8*(n-1) < LSB(32, A) <= 8*n      # 通过则 MLI = LSB(32, A)
3) b = 8*n - MLI，右端 b 个补齐字节全为零
```

第 2 条常被写反：它是**左开右闭** `(8(n-1), 8n]`。
n=2 时合法 MLI 只有 9..16（8 个值），`MLI == 8` 是非法的
——因为 m=8 应当走 n=1 的 ECB 分支，不该出现在 n=2 的包装体里。
第 3 条的 `b` 可能为 0（无补齐），此时检查恒成立。

自检用**成对用例**覆盖：同一份密文，只改一个开关（MSB / MLI / 最后一个补齐字节），
验证"应通过的通过、该拒的拒"，并且断言错误信息落在对应的检查编号上。

### 2.3 长度与边界

| m（明文字节） | 补齐后 | n | 密文字节 |
|---|---|---|---|
| 1..8 | 8 | 1 | 16 |
| 9..16 | 16 | 2 | 24 |
| 17..24 | 24 | 3 | 32 |

密文恒为 `8*(ceil(m/8)+1)` 字节。明文可到 `2^32` 字节（MLI 是 32 位字段，§1 line 82），
但 `m == 0` 非法。

## 3. 实现要点与实测

### 3.1 AES 自带，不调库

`aes_core.py` 从 GF(2⁸) 乘法逆 + 仿射变换现算 S-box（不硬编码表），
`state[r][c] = block[4*c+r]` 按列填充，ShiftRows 第 r 行左移 r 字节。
密钥长度 16/24/32 → Nk 4/6/8 → Nr 10/12/14；**Nk=8 时 `i % Nk == 4` 要多做一次 SubWord**，
这是 256 位密钥独有的分支，漏了只影响 AES-256，容易被 AES-128 的单测掩盖。

### 3.2 断言构成（3973 条，实跑全绿）

| 部分 | 条数 | 依据 |
|---|---|---|
| GF(2⁸) / S-box 性质 | ~55 | 定义直推（排列、互逆、单位元、`xtime(0x80)=0x1b`） |
| FIPS 197 附录 C 逐轮值 | ~600 | 附录 C.1/C.2/C.3 的 `start/s_box/s_row/m_col/k_sch` |
| RFC 3394 §4 分组中间值 | 192 | §4.1-§4.6 每一步的 `Enc` 行（96 组 × 加解密） |
| RFC 3394 包装 | 30 | §4 六组向量 + 移位式对拍 + 往返 |
| 篡改漏报集 | 1536 | 六个密文**逐位**翻转，全部必须被拒 |
| 支持集探针 | 12 | `C[0]` 是否依赖每个 `P[i]` |
| RFC 5649 | ~20 | §6 两组向量 + AIV 字段直读 |
| AIV 三检查配对 | 12 | MSB / MLI / 补齐字节各一组正负对照 |
| 长度扫描 | ~360 | m=1..40 × 三种 KEK |

### 3.3 关于「逐位翻转必拒」

这条断言是**经验性的，不是可证的**：固定 K 时解包是 128 位块上的双射，
能保证 `C` 变则 `(A, P)` 变，但推不出「`A` 单独一定变」。
1536 个位上全部实测被拒，碰撞概率约 `2^-64`，已在自检注释里标注 `[经验探针]`。
可证的那部分（双射 → 往返必还原）是分开断言的。

## 5. 踩坑记录

1. **逐步表格是索引式不是移位式**（§1.2）。偶数步全对、奇数步全错是它的指纹。
2. **抽取脚本的正则要按 token 切，不能按 8 位十六进制切**。
   RFC 里 KEK 是 `000102030405060708090A0B0C0D0E0F` 一整串 32 字符，
   `\b[0-9A-F]{8}\b` 因为词边界匹配不到任何一个 8 位片段，静默返回空。
3. **RFC 里 `KEK:` 和值之间有时没有空格**（§4.3 是 `KEK:000102...`），
   按列对齐解析的脚本会读到下一行的 Key Data，把 KEK 错填成明文。
4. **密文输出会跨物理行**（§4.4/§4.5/§4.6 的 Ciphertext 有续行），
   只取首行会得到被截断的向量，而且"长度是 8 的倍数"这一关还过得去。
5. **FIPS 197 附录 C 的 `round[0].k_sch` 只有前 16 字节**，
   AES-192/256 的完整密钥要读节标题下的 `KEY:` 行，`round[r].k_sch` 只是第 r 轮轮密钥。
