## 核心研究主题

- **执行计划**：plan node 树、cost 估算口径、EXPLAIN vs EXPLAIN ANALYZE

## 已确认的权威口径（PostgreSQL 官方文档《Using EXPLAIN》实读）

- 查询计划是一棵 **plan node 树**；底层是扫描节点（顺序扫描 / 索引扫描 / 位图索引扫描），
  其上是连接、聚合、排序等节点。`EXPLAIN` 每个节点输出一行，带代价估算。
- `cost=0.00..445.00` 的形式是 **启动代价..总代价**：启动代价是「输出阶段开始前的时间」
  （例如排序节点做完排序的时间），总代价按「该节点跑到底」估算。
- **上层节点的 cost 包含所有子节点的 cost**——所以顶层节点那一行就是整个计划的估算总代价，
  也是规划器要最小化的目标。
- 代价单位是**任意单位**，传统做法以一次磁盘页抓取为 1（`seq_page_cost = 1.0`），
  其余代价参数相对它设定；具体数值依赖平台。
- **cost 不关心「把结果转成文本 / 传回客户端」的开销**——规划器改变计划也影响不了这部分，
  但它可能是真实耗里的大头，所以「估算代价低但实际慢」有结构性原因。
- `ANALYZE` 的统计是**随机采样**而非精确值，所以估算的 rows/cost 会轻微波动。
