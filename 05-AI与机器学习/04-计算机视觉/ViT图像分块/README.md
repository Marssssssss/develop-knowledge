# ViT 图像分块(Patch Embedding 与位置编码)

## 简介

ViT 的核心主张只有一句话:**图像不需要卷积,切成一串 patch 交给标准 Transformer 就够了** ——
前提是数据量足够。本目录把这个主张里**可以离线验证**的部分全部实现并断言:
分块几何、patch embedding 与 `stride = patch` 卷积的严格等价、位置编码与置换对称性的关系、
Pre-LN 残差结构、参数量与算力构成、以及"缺少归纳偏置"这一代价的定量表现。

不训练模型、不下载权重 —— 分块与嵌入是纯粹的坐标变换与线性代数,可以逐条钉住。

```
python/  vit_patch.py(分块/嵌入/位置编码/编码器)  vit_patch_check.py(自检 33 条,A~F 六段)
go/      vit_patch.go(分块与几何)  vit_encoder.go(Pre-LN 编码器与参数统计)  main.go(自检)
```

> Go 侧拆 3 个文件是为守住「单文件 ≤ 300 行」的硬约束,属同一 `main` 包,用 `go run .` 一次编译。

## 原理详解

### 1. 分块:`N = H·W / P²`

论文把图像 reshape 成展平二维 patch 的序列。224×224、P=16 时网格是 **14×14,即 N = 196**
(自检 A 段);每个 patch 展平后长度 `P²·C = 256·3 = 768`,所以线性投影的输入维度就是 768。
展平顺序是 `(patch_y, patch_x, channel)` —— 顺序搞错不会报错,只会悄悄训不动。

**非整除要小心**:225×225 配 P=16 仍然只有 14 列,覆盖 16 + 13·16 = **224 px**,
最右一列像素被**静默丢弃**。步长也是:stride=8(< patch,重叠)会让 token 数涨到 **729**;
stride=20(> patch)只剩 **121** 个 token 且丢掉 8 px。只有 `stride = P` 才是不重叠且不丢像素的选择。

**混合架构**:论文也让 ViT 直接吃 CNN 的特征图。ResNet50 在 224 输入下的输出是 14×14×1024,
把它按 P=1 分块同样得到 **196 个 token**(维度 1024)—— 与像素级 P=16 的 token 数天然对齐。

### 2. patch embedding 就是 `stride = patch` 的卷积

论文写的是"用一个可训练的线性投影把 patch 映射到 D 维"。这与
`Conv2d(in=3, out=D, kernel_size=P, stride=P)` **完全等价** —— 只是权重在内存里的排布不同:
线性层那一维的索引是 `(dy·P + dx)·C + c`,卷积核是 `[C][P][P]`。

自检 B 段把同一组权重按两种排布各算一遍,输出**逐元素一致**(最大差异 2.49e-14,纯浮点重排):
这条等价性让"用卷积实现 patch embedding"成为合法的工程优化,也解释了为什么它只需要
**589,824 = P²·C·D = 256·3·768** 个参数(无 bias)。

### 3. [class] token

论文在 patch 序列**前面**拼接一个可学习的 `[class]` 向量,序列长度变成 **N+1 = 197**;
分类时只取它的输出(`y = LN(z_L^0)`)。它不是卷积式的"全局池化",而是让**注意力自己去汇总**:
自检 C 段证实,只改动第 4 个 patch 的某个分量,`[class]` token 的输出就变了(变化 0.217638),
即**第一层就具备全局感受野**。

### 4. 位置编码:置换等变的破除者

Transformer 的自注意力对 token 顺序是**置换等变**的:把输入 token 重排,输出只是同样重排。
自检 C 段用一个 6-token、D=4 的确定性小模型验证了这一点 —— 不加位置编码时,
置换前后的输出差异是 **0.00e+00**(精确为零);而加上位置编码后,同样的重排带来
**0.640767** 的差异。

**这就是位置编码存在的意义**:它是唯一让模型"知道顺序"的东西。反过来说,ViT 的**全部**空间信息
都压在这 197×768 = **151,296** 个可学习参数里(自检 C 段)。

论文试过 2D-aware 的位置编码,结论是"没有观察到性能增益"。一个可量化的解释:
行优先展平后,1D 下标相邻的 token 里有 **182/195 = 93.33%** 同时是空间**水平**相邻;
而空间**垂直**相邻的 token 在 1D 序列里的距离**恒为 W/P = 14**(自检 C 段)——
也就是说,1D 顺序已经隐含编码了绝大部分二维结构,额外的 2D 设计没有多少剩余空间可补。

### 5. Pre-LN 编码器

论文的式 (2)(3) 是 **Pre-LN**:

```
z'_ℓ = MSA(LN(z_{ℓ-1})) + z_{ℓ-1}
z_ℓ  = MLP(LN(z'_ℓ)) + z'_ℓ
```

注意 LN 在**子层内部**(归一化的是子层的输入),残差加的是**子层输出**而不是归一化结果。
自检 D 段用"把子层输出置零"的方式验证这一点:把 V 的投影置零后 MSA 输出恒为 0,
再把 MLP 的输出也置零,整个块**精确退化为恒等映射**(差异 0.00e+00)——
说明残差是对 LN 之后的子层输出做加法,而 LN 不改变恒等性。

同段还钉住了几个基础量:LayerNorm 输出均值 0、方差 **0.999992**(eps=1e-5 使其略小于 1,
不是精确的 1);GELU(1) = **0.841192**(tanh 近似);注意力权重按行 softmax 和为 1 且对整体平移不变。

### 6. 缺少归纳偏置:平移行为

论文自述的代价是"Transformers lack ... translation equivariance and locality"。
这句话可以在分块层面直接量化:

| 平移量 | patch 序列的行为 |
|---|---|
| **16 px(= P)** | 序列只是位置重排,内容**逐元素相同**(13/14 的列完全对齐) |
| **1 px** | **全部 196 个 patch** 的内容都变了(patch 0 差异 0.909091) |

也就是说,分块本身只在"整 patch"这一特殊位移下等变;真实世界的连续位移会改变**每一个** token。
这是 ViT 需要大规模预训练(或用 CNN 特征做混合输入)的直接原因。

另一个角度是感受野:覆盖 224 px 需要 **112 层** 3×3 卷积(感受野 = 1 + 2L),
而 ViT 只需 **1 层**全局注意力 —— 代价是注意力的 N² 项。

### 7. 参数与算力构成

论文 Table 1 给出 ViT-Base 是 **86M**。自检 E 段把它逐项拆开:

| 部分 | 参数量 |
|---|---|
| patch embedding(P²·C·D,无 bias) | 589,824 |
| 位置编码((N+1)·D) | 151,296 |
| 12 层编码器(注意力 4D²+4D;MLP 8D²+5D;两个 LN) | **85,054,464** |
| 末尾 LN + 1000 类单层头 | 770,536 |
| **合计** | **86,566,120 ≈ 86.57M**(与论文 86M 相对误差 0.66%) |

可见**参数几乎全在编码器里**(98.3%),而"图像分块"这件事本身只花了 0.59M。

算力上要盯住 `N²`:单头一层注意力的 QKᵀ 项是 `N²D = 196²·768 = 29,503,488` 次乘加;
**P 从 16 减半到 8 会让 token 数变成 4 倍(784),注意力矩阵面积变成 16 倍**
(38,416 → 614,656)。P 的选择本质是"细粒度 vs 二次代价"的取舍。

## 对比

| 维度 | ViT | CNN(ResNet) | 混合(R50 + ViT) |
|---|---|---|---|
| 归纳偏置 | 几乎为零 | 局部性 + 平移等变 + 层次 | 由 CNN 部分提供 |
| 全局感受野 | 第 1 层 | 需 ~112 层(224 px) | 第 1 层 |
| 位置信息 | 全靠 197×768 位置编码 | 由卷积结构天然携带 | 同 ViT |
| 平移等变 | 无 | 有 | 部分 |
| 数据需求 | 极大(JFT-300M 级) | 中等 | 较小 |

## 关键代码片段

```python
# 分块:行优先,每个 patch 展平顺序为 (patch_y, patch_x, channel)
for ry in range(rows):
    for rx in range(cols):
        vec = []
        for dy in range(patch):
            for dx in range(patch):
                vec.extend(img[ry * stride + dy][rx * stride + dx])

# 位置编码必须显式相加,否则整个模型对 token 顺序置换等变
z0 = add_pos(patch_tokens, pos_embed)        # 论文式 (1):[class] + patch·E + E_pos

# Pre-LN 残差:残差加在子层输出上,而非归一化结果上
z1 = [[a + b for a, b in zip(t, h)] for t, h in zip(tokens, attention(layernorm(tokens)))]
```

## 性能与边界

- **注意力是唯一的二次项**:`O(N²D)`,N = 196 时尚可(29.5M / 层 / 头),
  但高分辨率微调时 N 会随 (H/P)² 增长,通常要靠插值位置编码 + 局部/稀疏注意力来压;
- **位置编码插值**:微调分辨率与预训练不同时,必须对位置编码做插值,否则序列长度对不上;
- 边界:**小数据下不如 CNN**(论文的核心警告),**极高分辨率下注意力代价爆炸**,
  **细粒度任务**(分割/检测)需要更高分辨率的 token(更小的 P)或特征金字塔。

## 注意事项与常见坑

1. **非整除尺寸静默丢像素**:225 配 P=16 只覆盖 224 px。要么 resize 成整除尺寸,要么显式补边。
2. **展平顺序是隐性契约**:`(patch_y, patch_x, c)` 与 `(c, patch_y, patch_x)` 得到的 patch 长度相同,
   线性层照样能跑,但权重语义完全不同 —— 跨实现迁移权重时最容易在这里出错。
3. **位置编码漏加不会报错**,只会让模型彻底失去空间信息(置换等变);自检里的 0.00e+00 差异
   就是"漏加"时的表现。
4. **1D 位置编码并不像看上去那么弱**:93.33% 的 1D 邻接天然是水平邻居,垂直方向靠固定间隔 14
   隐式编码 —— 这解释了论文"2D-aware 无增益"的观察。
5. **Pre-LN 的残差位置别写反**:LN 在子层输入侧,残差加的是子层输出;写成 Post-LN 或把残差加到
   归一化结果上,自检里的"退化恒等"测试就会失败。
6. **P 减半的代价是 16 倍的注意力矩阵**,不是 4 倍;算显存时按 N² 估。
7. **ViT-Base 的 86M 里 98.3% 在编码器**,patch embedding 只占 0.59M —— 想压缩模型不必从分块层下手。
