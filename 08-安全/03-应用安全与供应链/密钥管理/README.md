# 硬编码凭据检测：熵阈值为什么会系统性漏报

**CWE-798（Use of Hard-coded Credentials）** 的可利用性被标为 **High**。
它有两个变体（MITRE 定义）：

- **Inbound**：产品自带认证逻辑，把输入与内置凭据比对（默认管理员账号）。
  每个安装的密码**都一样**，管理员往往改不掉也检测不到。
- **Outbound**：产品用它去连另一个系统（前端里塞着后端凭据）。

规范给的缓解措施里，和「检测」并列重要的是**架构层**：Inbound 不要内置默认口令
（改走 first-login 模式）、必须留存时用强单向哈希 + **随机盐**、把凭据放到代码之外。
但无论架构多好，**已经进仓库的凭据**仍然要靠扫描发现——这就是本 demo 的主题。

## 原理详解

### 1. 香农熵的上限由字符集决定

长度无关地看，一个串的香农熵满足 `H ≤ log2(|A|)`，等号在字符均匀分布时取得：

| 字符集 | \|A\| | H 上限（bit/字符） |
| --- | --- | --- |
| 十六进制 | 16 | **4.0** |
| 大小写字母+数字 | 62 | 5.95 |
| Base64 | 64 | **6.0** |
| 字节 | 256 | 8.0 |

所以「熵 ≥ 4.5 即告警」这个在许多教程里出现的阈值，
**对十六进制密钥永远不可能成立**——一个 40 位的高质量十六进制 token
熵最多 4.0，实测 3.959，直接被漏掉。

本 demo 语料里 `api_token`（40 位十六进制）与 `aws_key` 都因此被 D1 漏报。

### 2. 归一化：除以 log2(|A|)

把熵除以**观测字符集**的对数，得到 `H / log2(|A|) ∈ [0,1]`。
十六进制串归一化后同样能接近 1.0，跨字符集可比了：

```
item                   H(bit)   |A|    H/log2|A|  truth
aws_key                3.684    14     0.968      SECRET
api_token              3.959    16     0.990      SECRET
jwt_secret             4.503    25     0.970      SECRET
vendor_sk              4.682    28     0.974      SECRET
git_sha                3.737    15     0.957      -
request_id             3.391    14     0.891      -
png_b64                3.653    23     0.808      -
api_url                4.522    26     0.962      -
```

但归一化熵**只对足够长的串有意义**：`1.2.3` 的归一化熵是 0.961、`password123`
是 0.987——短串天然「很均匀」。所以必须加**长度门槛**（本 demo 取 20）。

### 3. 存在「任何阈值都分不开」的样本对

语料里 `aws_key`（真密钥）的熵是 **3.6842**，`git_sha`（非密钥）是 **3.7373**——
**密钥的熵比非密钥还低**。这意味着不存在任何裸熵阈值能同时做到
「命中 aws_key 且不命中 git_sha」。

阈值扫描（3.0 → 5.0，步长 0.01）给出的量化结论：

- 所有阈值里最高召回只能到 **TP=4**（长密钥共 4 条）
- 在**零误报**的约束下，召回最多只能到 **TP=1**

这不是调参能解决的，是判据本身的**信息量不足**——必须引入熵之外的信号。

### 4. 三级检测器

| 检测器 | 判据 | TP | FP | FN | TN |
| --- | --- | --- | --- | --- | --- |
| D1 | 裸熵 ≥ 4.5 | 2 | 1 | 3 | 4 |
| D2 | 归一化熵 ≥ 0.90 | 4 | 2 | 1 | 3 |
| D3 | 归一化熵 **OR** 结构规则 **OR**（变量名关键字 AND 熵 ≥3.0），白名单优先 | 5 | 1 | 0 | 4 |

D3 的三个信号各司其职：

- **结构规则**（`AKIA[0-9A-Z]{16}`、`tok_live_...`、PEM 头）：救回 `aws_key`、
  `vendor_sk` 这类**有固定前缀**的凭据——它们的熵并不突出。
- **变量名关键字**：救回 `password123` 这种**低熵但确实是凭据**的串。
- **上下文白名单**（名字含 sha/commit/digest/uuid/version/hash）：干掉 `git_sha`
  这个「高熵但显然不是凭据」的误报。

残留的 1 条误报是 `api_url`（URL 是高熵串），要靠**值形状规则**
（`^https?://`）才能排除——本 demo 故意留着它，说明 10 条语料上的完美成绩不值得信任，
真正有意义的是**每一级改进各自修掉了哪一类错误**。

### 5. 检测只是前半段

CWE-798 的 Inbound 变体有个残酷特性：**凭据对所有安装实例都一样**。
所以扫描到之后，轮换（rotation）不是可选项——只要凭据还有效，
删掉代码里的那一行并不会让它失效。这也是规范把
「把凭据放到代码之外、强哈希+随机盐、first-login」列为**架构与设计阶段**
缓解措施的原因：它们让「泄露」这件事的爆炸半径变小。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `secret_scan.py` | 熵/归一化、规则、语料、三级检测器、阈值扫描、不可分性判定 |
| `secret_scan_selftest.py` | 31 项断言 |
| `secret_scan.go` | Go 版（regexp 实现规则） |
| `secret_scan.c` | C 版（**无正则**，规则用子串匹配实现；判据与判定结果一致） |

## 运行

```bash
python secret_scan.py             # 打印熵表 + 三级检测器对照
python secret_scan_selftest.py    # 31 项断言
go run secret_scan.go
cc -o scan secret_scan.c -lm && ./scan
```
