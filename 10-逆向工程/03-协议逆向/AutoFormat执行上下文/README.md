# AutoFormat：用"执行上下文"把报文切成层次结构

> ExeT-based 路线的代表作。Z. Lin, X. Jiang, D. Xu, X. Zhang, *Automatic Protocol Format Reverse Engineering Through Context-Aware Monitored Execution*, **NDSS 2008**。核心洞察只有一句：**同一个报文里不同的字段，通常在不同的执行上下文（典型是运行期调用栈）中被处理**——于是"谁在什么时候读了第几个字节"本身就编码了格式。

## 一、简介

NetT 路线（如 Discoverer）只有网络轨迹，能拿到语法但拿不到程序语义；Polyglot 一类的动态污点分析能拿字段，却只给出**扁平**结构。AutoFormat 要解决的就是后面这半句：不只抽字段，还要还原**非扁平的层次结构**。

论文自评：在 7 个协议 30+ 条报文上，与 Wireshark 相比**最细粒度字段的平均精确匹配率 93.4%**，并能给出字段间的层次 / 并行 / 顺序关系。

## 二、原理详解

### 2.1 上下文感知执行监视（§3.1）

先拦截 `sys_socket` 一类的系统调用，把收到的报文**逐字节标记**上它在整条报文中的偏移；随后在整个处理生命周期里插桩两类指令来传播标注：

| 指令 | 规则 |
| --- | --- |
| 数据搬移（如 `mov`） | 源被标记 → 目的继承源的标注；**源未被标记 → 取消目的的标记** |
| 算术 / 逻辑（如 `add`/`mul`/`and`） | 两个被标记的操作数 → 标注取**并集**；只有一个 → 继承它；都没有 → 取消 |

> **mov 不产生信息**：论文与 Tupni 都强调，mov 不"处理"操作数，因此不贡献字段尺寸信息，计算权重时要忽略。

每当**被标记的内存被读**，落一条记录：

```
<o, c, s, l>    o = 该字节在整条报文中的偏移
                c = 内容
                s = 读发生时的运行期调用栈
                l = 读指令的地址
```

调用栈通过遍历栈帧取返回地址获得；若二进制编译时**没开栈帧指针**，则插桩 call/ret 维护一个**影子调用栈**（本 demo 只记录栈本身，未复现影子栈机制，README 中标注）。

### 2.2 字段树生成（§3.2.1，Algorithm 1）

预处理：由于程序执行的局部性，同一偏移可能被反复读，**连续的完全相同的记录只保留一条**。

然后扫日志，**当且仅当**相邻两条记录满足

```
log[i].o == log[i-1].o + 1   且   log[i].s == log[i-1].s
```

就把偏移并入当前段 `p`；否则把 `p` 建成节点 `v` 并插入树：

1. 找到节点 `u`，使得 **`u` 包含 `v`、但 `u` 的任何子节点都不包含 `v`**；
2. 把 `u` 中那些区间是 `v` 子集的子节点**移交给 `v`**；
3. `v` 挂到 `u` 下。

> **论文伪代码的一处遗漏**：Algorithm 1 第 8–19 行的循环结束后直接 `Return`（第 21 行），**没有冲刷最后一段 `p`**。不补这一步，报文的**最后一个字段会整体丢失**。本 demo 在两个实现里都补了这次 flush，并把它写成断言。

注意合并判据**只比较调用栈 `s`，不比较指令地址 `l`**——`l` 被记录但对切分不起作用。层次结构来自"同一段偏移在更深的上下文里被再读一遍"：外层先建出大区间节点，内层的子区间因为被 `u` 包含而挂到它下面。

### 2.3 并行字段识别（§3.2.2，Algorithm 2）

**并行字段** = 在协议规范里**位置可互换**的字段（HTTP 的各首部）。它们通常在**同一个循环**里被处理，于是共享执行历史。

定义某个偏移的**执行历史** = 该偏移每次被读时的调用栈序列。论文取每个节点的**最低偏移**（首字节）来累计历史，理由是"一个字段里并非所有字节都被同等处理，首字节往往被处理得最多"。

**相似判据（脚注 3）**：两条历史的**公共前缀 ≥ 整个历史的 h%**，实验取 **h = 80**。

> 论文没有说明"整个历史"取长的一侧还是短的一侧。本 demo 取**较长的一侧**（更保守：要求公共前缀基本覆盖住更长的那条），并在代码注释里标注。

对每个父节点：把执行历史相似的子节点判为并行字段；若两个被标记节点之间夹着未标记节点，则左侧标记节点会带上这些未标记节点组成一个新的并行字段，并**插入一个层次节点**来代表它。

**阈值 h 直接决定误判**：本 demo 断言了同一对历史（公共前缀 3/4 = 75%）在 `h=80` 下不相似、在 `h=70` 下变成相似。

### 2.4 顺序字段与 BNF（§3.2.2）

对字段树做**前序遍历**，但**只列出叶子节点、以及"多个并行字段的父节点"**——这就得到一组顺序字段；再对每个代表并行字段的层次节点的**子树递归走一遍**，得到该并行字段内部的候选列表。树的拓扑天然决定了 BNF 里的嵌套关系。

> **一个真实的粒度下沉现象**：本 demo 的夹具里每个首部都还有一层"关键字解析"子节点，于是首部行节点本身**不是叶子**，被前序遍历跳过——候选列表下沉成了"各首部的关键字子字段" `[(25,37) (50,58) (63,69)]`，而不是三个首部行本身。这是 Algorithm 2 判据的直接后果，不是实现 bug。

## 三、与其他方法的对比

| 方法 | 输入 | 结构 | 特长 |
| --- | --- | --- | --- |
| Discoverer (2007) | NetT | 扁平 token 序列 | 不需要二进制 |
| Polyglot (2007) | ExeT | 扁平字段 | 关键字 / 方向字段 |
| **AutoFormat (2008)** | ExeT | **层次 + 并行 + 顺序** | 结构还原，可直出 BNF |
| Tupni (2008) | ExeT | 记录序列 + 记录类型 + 约束 | 约束可用于 0day 签名 |
| ReFormat (2009) | ExeT | 同 AutoFormat | **报文被加密也能做** |

AutoFormat 的局限（论文 §6 自述）：依赖能实际跑起来的二进制、单条报文只覆盖被走到的分支、**层次来自"再读一遍"这一行为特征**，遇到不同实现可能失真。

## 七、性能边界与注意事项

- **只在被读时落记录**：报文里从未被访问的字节**完全不会出现在日志里**，因此这些区间推断不出任何字段（这与 Tupni 的 "virtual field" 处理是同一类问题）。
- **单条报文 = 一条执行路径**：只覆盖被走到的分支，需要多报文聚合（论文 §6 自述局限）。
- **要求能跑**：需要 Valgrind / Pin / QEMU 一类二进制插桩框架（论文原型基于 Valgrind 3.2.3）。
- **h=80 是实验值**，不是理论值；见 2.3 的阈值敏感性断言。
- **层次依赖"重复读"**：若实现不二次读取某段偏移，就长不出层次节点，树会退化成扁平。

## 八、常见坑（本 demo 实跑暴露）

1. **忘记冲刷最后一段** → 最后一个字段整体丢失（2.2）；
2. **相似度分母取错** → 阈值敏感性断言立刻翻车；本 demo 固定取较长历史；
3. **前序遍历若不在并行节点处停下**，根层顺序列表会把并行字段的子节点也混进来（应得 4 项，实得 7 项）；
4. **Go 侧把三条首部写成一段连续同栈 span** → 三条首部在 Algorithm 1 里被合并成一个节点，Algorithm 2 再也找不出 3 个候选（必须在中间插入栈不同的解析段把它们切开）。
