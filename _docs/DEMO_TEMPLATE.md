# DEMO_TEMPLATE.md — Demo 模板与规范

每个 demo 目录都应严格遵循本模板。

## 〇、内容来源规则（最高优先级，违反即失败）

**任何 demo 的 README 内容都必须先联网查权威资料、再总结，禁止纯凭模型自身知识生成。**

1. **先查后写**：写 README 之前，必须用 `WebSearch` / `WebFetch` 查阅权威来源并阅读实际内容，再基于查到的资料做归纳总结。
2. **权威来源优先级**：
   - 官方文档 / 官方规范（如 man7.org、kernel.org、MDN、RFC、官方语言/框架文档、WG21/W3C 标准）
   - 经典著作与论文（如 Stevens《UNP》、相关论文）
   - 权威技术博客 / 知名工程团队文章（如 Cloudflare/Netflix tech blog）
   - ❌ 禁止依赖营销号、内容农场、无法溯源的转载
3. **可追溯**：README 的"参考资料"一节必须列出**实际阅读过**的链接（含标题 + URL），内容要能对应回这些来源。
4. **总结而非照抄**：对权威资料做提炼、对比、结构化，而不是复制粘贴原文。
5. **有冲突时**：以官方文档/标准为准，并在 README 中注明分歧点。

## 一、目录结构

```
<domain>/<subdomain>/<topic>/<point>/
├── README.md            # 必含：简介 + 环境 + 运行方式
├── c/                   # 可选
│   ├── main.c
│   └── README.md (可选)
├── python/              # 可选
│   ├── main.py
│   └── requirements.txt (可选)
├── go/                  # 可选
│   ├── main.go
│   └── go.mod (可选)
├── ts/                  # 可选
│   ├── index.ts
│   └── package.json
├── js/                  # 可选
│   └── index.js
├── java/                # 可选
│   └── Main.java
└── NOTES.md             # 可选：踩坑记录、设计取舍
```

每个 demo 至少 **2 种语言**，目标是**2-4 种**主流实现（C / Python / Go / TypeScript）。

## 二、README.md 模板（详细版）

README 是 demo 的核心交付物，**必须详尽**：读者只看 README 就能理解原理、复现运行、知道去哪深入。所有技术陈述以第〇节查到的权威资料为依据。

```markdown
# <知识点名称>

## 简介
- 2-3 句话讲清它是什么、解决什么问题、适用场景
- 关键概念清单（3-5 个，各附一句话解释）
- 历史背景（谁提出、解决什么痛点，1-2 句）

## 原理详解
- 工作机制分步说明（编号列表，每步一句关键动作）
- 核心数据结构 / 状态机 / 系统调用流程（用 ASCII 图或表格）
- 核心 API 及关键参数说明（签名 + 每个参数含义 + 返回值 + 错误码）
- 底层发生了什么（内核/运行时视角，引用权威资料）

## 对比 / 选型
（如适用：与其他实现的对比表，维度含性能特征、复杂度、适用规模、平台支持）

## 环境准备
- 操作系统：
- 语言版本：
- 依赖：

## 运行方式
### C
\`\`\`bash
gcc -O2 -Wall -Wextra main.c -o demo
./demo
\`\`\`

### Python
\`\`\`bash
python3 main.py
\`\`\`

## 关键代码片段
（贴 20-50 行核心实现，逐段注释说明对应"原理详解"中的哪一步）

## 性能与边界
- 时间/空间复杂度或量级数据（注明来源）
- 规模上限、平台限制（如 fd 数量、操作系统差异）

## 注意事项与常见坑
- 已知坑（每个坑说明：现象 → 原因 → 规避方法）
- 跨平台差异
- 生产环境建议（如适用）

## 参考资料（实际阅读过的权威来源）
- [标题](URL) — 一句话说明该来源提供了什么
- 至少 2 个，优先官方文档/RFC/man pages
```

## 三、代码风格

| 语言 | 风格 |
| --- | --- |
| C | `-Wall -Wextra -pedantic` 编译干净 |
| Python | PEP 8，`python3 -m py_compile` 通过 |
| Go | `gofmt -d` 无输出 |
| TypeScript | `tsc --noEmit` 通过 |
| Java | 编译干净 |

## 四、禁止项

- ❌ 引入复杂框架（如 Flask、Spring）来写一个最小 demo
- ❌ 注释里写"这里不解释"
- ❌ 引入网络资源（CDN 库、远程图片）
- ❌ 中文变量名（C/Go 等主流语言习惯）
- ✅ 注释充分，函数命名语义化
- ✅ 错误处理完整（C 检查返回值，Python 抛异常）
- ✅ 跨语言命名一致（如 `select_demo.c` / `select_demo.py` / `select_demo.go`）
