# AUTOMATION_PROMPT.md — 自动巡检任务提示词（唯一权威）

> 本文件是「开发研究-自动巡检」**12 条定点任务的唯一权威流程定义**。每条任务的 prompt 只写「槽位号 + 硬不变量摘要 + 指向本文件」；摘要与本文件冲突时，**以本文件为准**。
> 最后修订：2026-09-14（调度模型由「单条 2h 滚动」→「12 条每日定点」）

## 〇、调度模型（为什么是 12 条 DAILY 任务）

- 全天 **12 条**独立任务：`开发研究-自动巡检 00:00 / 02:00 / 04:00 / … / 22:00`，每条 `FREQ=DAILY;INTERVAL=1;BYHOUR=<H>;BYMINUTE=0`，**每天只触发一次**，触发时刻锁定 `<H>:00`（调度器 tick 30 s，实际落地 `H:00:00 ~ H:00:30`）。
- **为什么不继续用单条 `FREQ=HOURLY;INTERVAL=2`**：本机调度器算下一次运行时刻的公式是 **`nextRunAt = 上一轮 finishedAt + INTERVAL`**（实现：`schedule-utils` 的 `nextHourly` + `advanceNextRunAt(db, id, finishedAt)`）。每轮耗时 10~30 分钟会**全额累加**到下一次触发上：实测平均间隔 **137 分钟**、11 轮累计漂移 **3 小时 11 分**、约 **+2 小时/天**，从 13:46 一路漂到次日 14:56。文档里的「每 2 小时整点」在 HOURLY 模型下**永远不可能成立**，改 RRULE 治不了。
- **DAILY 为什么不会漂**：`DAILY` 走 `nextDaily` —— 在「完成时刻之后」找**下一个日历点 `<H>:MM`**，天然自校准。08:00 那轮 08:26 结束，下一条仍是明天 08:00，误差不累积。
- 取舍：① 想改触发时刻，要改 **12 条**任务的 `BYHOUR`；② 某槽被「轮间保险」拦掉后，该任务**当天不再补跑**（次日正常）。
- **禁令**：不要新增任何 `FREQ=HOURLY` 的巡检任务；不要给 DAILY 规则写逗号列表 —— 解析器 `parseClampedInt` 只取整数值，`BYHOUR=2,4` 会被静默解析成 `2`；不要给 HOURLY 传 `BYHOUR/BYMINUTE`（对 HOURLY 完全无效）。

## 一、每轮固定动作（严格按顺序）

1. **读状态**：只读 `_docs/STATE.md`（≤ 5 KB），取 §一 索引表与 §二「本轮状态」。
2. **轮间保险**：见 §二，不通过即退出。
3. **定位领域(大类严格轮转)**：本轮大类 = §一「大类循环」的第 `top_pos` 位；子类目 = 该大类在索引表的全部条目(按表序)中第 `sub_pos[大类]` 个。
4. **轮转推进**：完成后 `top_pos = (top_pos+1) mod 12`、`sub_pos[大类] = (sub_pos[大类]+1) mod 该大类条目数`。**禁止**按 priority_score / done_count / 临时偏好挑领域(旧机制 2026-09-16 已废)。该规则保证 12 个大类各占 1/12 轮次，杜绝「A→B→A 来回抓」与部分大类过频。
5. **5 个主 demo**：全部落在所选索引对应的细分领域；每个 demo = `README.md` + ≥1 代码文件，多语言同题只算 1 个。
6. **副任务 ≤ 2**：S1 已有 demo 增强 / S2 目录补全 + 类目自动拓展（每轮 ≤2 子类目；顶层默认不新增，2026-09-22 用户新增 `12-项目工程` 后共 **12 个顶层**）/ S3 索引同步。
7. **收尾**：归档 + Git 同步 + 企业微信通知（见 §四）。

## 二、轮间保险（开局必做）

- 读 §二 `last_run`：距当前时间 **< 45 分钟 → 立即退出**，不写文件、不推送、不通知。
- 阈值依据：定点槽间隔 120 分钟、正常轮次耗时 10~30 分钟，因此 45 分钟内的「上一轮」不可能是本槽的正常上一轮，只可能是 **重复派发 / 应用重启后的补偿派发 / 长时间休眠后多槽同时补跑**。
  - 历史上用 80 分钟，在定点模型下会**误杀**：某轮 16:58 结束时写下 `last_run`，18:00 的正常槽距它只有 62 分钟，会被当成重入而白丢一轮。故下调为 45 分钟。
- ≥ 45 分钟 → 正常执行，并在第 3 步（定位领域）后**立即**把 `last_run` 更新为当前时间 + commit（占位锁）。
- 多槽同时补跑时只放行先到的一条，其余自动退出；被拦掉的槽当天不补。

## 三、配额、内容铁律与失败回退

| 项 | 规则 |
| --- | --- |
| 主任务 M | **必 5** 个新 demo（同一细分领域） |
| 副任务 S | **≤ 2**，可 0（S1/S2/S3 三选一，可并用） |
| 硬约束 | ≤ 5 `agentic_search` / ≤ 15 `WebSearch` / ≤ 10 `WebFetch` / ≤ 5 新 demo，超出即止，**不消耗搜索额度凑数** |
| 单 demo 体量 | 单源文件 ≤ 300 行、README ≤ 200 行（`OPTIMIZATION.md` §1.1） |

- **降级规则**（`SCHEDULE_QUOTA.md` §三）：上轮已完成 ≥5 demo → 本轮主任务可降级为 S1/S2/S3 × ≤2；上轮失败/跳过 → 本轮主任务**必做**（不允许连续 2 轮无新 demo）；同一领域连续 ≥5 轮无新 demo → 强制切下一个索引。
- **内容来源铁律**：任何 README 必须先联网查权威资料（官方文档 / RFC / 经典著作 / 权威工程博客，禁内容农场）→ 阅读 → 归纳；参考资料必须列出**实际读过**的链接；**禁止纯凭模型自身知识生成**。
- **单轮失败重试 3 次 → 跳过该子类目**（`sub_pos` 照常推进）并记入 §二 `failed_attempts` → 连续跳过 5 个 → 暂停巡检 + 告警用户（`STATE.md` + `archive/schedule.md` 同步记录）。
- **不实际运行 demo 代码**（本机无 C/Go/Swift/Kotlin 工具链时走人工代码审查）。

## 四、收尾清单

1. `_docs/STATE.md`：§三「最近 5 轮」滚动追加；§二 刷新 `top_pos` / `sub_pos` / `last_run` / `last_top` / `skipped` / `failed_attempts`。
2. `_docs/archive/completed.md`：每 demo 一行；`_docs/archive/schedule.md`：每轮一行（含 notify 三态枚举，见 `WECOM_NOTIFY.md` §十）。超过 100 / 30 行时 rotate。
3. `.workbuddy/memory/YYYY-MM-DD.md`：追加当日累计。
4. **Git 同步**（`GIT_SYNC.md`）：任何更改完成**立即** `git add -A && git commit && git push`（改完即同步，不等本轮结束）；push 前 `git pull --rebase origin main`；冲突走告警不自动 merge；**禁止 force push**；commit 消息 `auto: YYYY-MM-DD HH:MM - <简述>`。
5. **企业微信通知**（`WECOM_NOTIFY.md`）：Git 同步后推一条 markdown 摘要（领域 + 推进量 + 5 个 demo 路径 + 各自 1 句核心机制，核心机制须基于本轮实际查到的权威资料）。**每轮只 curl 一次**，禁止重试/重发/补发；发送前检查 `schedule.md` 是否已有本轮 `notify: ok`；curl 模板禁止 `-o` 写 /tmp（Git Bash exit 23 quirk），用命令替换捕获响应体；失败只记三态（`ok` / `failed <reason>` / `skipped <reason>`），**不阻塞**，连续 5 轮失败升级告警；凭据缺失 → `skipped`。

## 五、时间戳铁律（2026-09-14 新增）

- 一切时间戳（commit 消息、`STATE.md.last_run`、`archive/*` 行首、daily log）**必须来自 shell `date` 的实际输出**。
- **禁止**推算（如 `last_run + 2h`）、**禁止**沿用上一轮 / 上一日 / 记忆里出现过的时间字符串。
- 事故：2026-09-14 那轮真实运行区间是 12:40~12:56（git 提交时间可证），却把本轮时间记成 `14:30`（疑似照抄 09-12 同一索引的历史行），导致 14:56 的触发点误判「距上轮仅 27 分钟」而自我退出，**白丢一轮**。
- **执行方式（2026-09-18 新增，强制）**：commit 消息里的时间串必须用
  `git commit -m "auto: $(date '+%Y-%m-%d %H:%M') - <简述>"` 的**命令替换**生成，
  archive/daily log 的时间列同样先跑 `date` 再抄。**手写时间必错**——2026-09-18 00:00 槽
  手写了 6 条 commit 消息时间，其中两条（标 `00:38` / `01:15`）超出真实收尾时刻
  （实测 00:29~00:31）15~47 分钟，与 09-17 14:00 槽同一失误。历史提交不重写（禁 force push），
  只能在 `archive/schedule.md` 本轮行标注「以 schedule.md 行为准」。

## 六、自检

- 触发时刻应等于本任务的 `BYHOUR:00`（±2 分钟）。明显不符 → 记 `notify: failed slot_mismatch` 并告警用户（说明 12 条任务被改动或调度器异常）。
- 修改 RRULE 后必须用 `automation list` 的 `nextRunAt` 复核下一轮时刻是预期值，不是预期就当场修。
- 归零/重建调度前先确认：上一轮已完成（`schedule.md` 有 `notify: ok`），否则删除任务会中断在跑的会话（2026-09-14 曾因此产生一条 `run failed: Conversation ended before automation request completed`，当轮成果已提交、无损失）。
