# 09 语言学习

> 与 01-08 按"领域/知识点"组织不同,本目录按**编程语言**组织。
> 目的:沉淀每种语言的**语言机制级**知识点(语法糖、运行时特性、标准库惯用法),与"领域原理"互补。

## 为什么单独建这个维度?

- **领域目录**关心"这件事怎么做" —— 比如 IO 多路复用、REST 设计、碰撞检测
- **语言目录**关心"这种语言本身的写法与坑" —— 比如装饰器、GIL、生成器、async/await、错误处理

两者经常交叉:同一知识点(IO 多路复用)在不同语言里有完全不同的写法。领域目录里的 demo 通常已经覆盖了主流语言,但**只触及该知识点的相关 API**;本目录会深入到"语言本身的特性",不受具体场景限制。

> 第二批(2026-09-19)`闭包与迭代器/`、`无畏并发/`、`async状态机/`、`错误处理惯用法/`、

> TypeScript 于 2026-09-15 16:00 槽按类目拓展规则登记(状态 🗺 = 目录与路线图已建、demo 待做)。
> TypeScript 首批 5 个 demo(2026-09-19 22:00 槽):`结构类型/`、`条件类型与分发/`、`映射类型与修饰符/`、
> `类型收窄与守卫/`、`方差与可赋值性/` —— 共同点是把「类型系统的结论」变成**可执行的断言**:
> 每个 demo 都带 `types/*.ts` 编译期 fixture(用 `tsc --strict` 精确比对期望错误码集合)和
> 一个 node 可直跑的主 TS(Node 22 起内置类型擦除),后者专门演示「运行时的原生行为」与
> 「编译期的类型结论」之间的落差 —— 例如谓词撒谎能让编译通过却在运行时抛 `TypeError`,
> 双变让窄参数回调编译通过却在运行时读到 `undefined`。
> Golang 第三批 5 个 demo(2026-09-18):`内存分配器/`、`逃逸分析与内联/`、`内存模型与sync原语/`、
> `反射三定律/`、`unsafe与内存布局/` —— 从"运行时怎么放内存"走到"编译器怎么决定放哪、以及
> 人可以绕过类型系统到什么程度"。
> Python 第四批 5 个 demo(2026-09-20 20:00 槽):`迭代器协议与itertools/`、`MRO与C3线性化/`、
> `参数绑定与调用约定/`、`运算符与特殊方法分派/`、`作用域闭包与单元变量/` —— 五个都是
> 「**解释器替你做的决定**」:迭代器与容器的分野、多继承里谁先被调用(按 CPython `pmerge` 复刻后
> 与 `__mro__` 对拍)、实参怎么填进形参(手写绑定算法与 `inspect` 对拍)、`NotImplemented` 触发的

> 而引发的 `UnboundLocalError` 与类作用域对推导式不可见的静默陷阱。
> Golang 第四批 5 个 demo(2026-09-21 18:00 槽):`定时器与四叉堆/`、`netpoll与网络轮询器/`、

## 目录内约定

每种语言的子目录内部:

```
Python/
├── README.md            # 语言特性总览 + 学习路径 + 与其他语言的关键差异
├── 装饰器/              # 一个语言特性 = 一个 demo
│   ├── README.md
│   ├── basic.py
│   └── with_args.py
├── 生成器/
└── ...
```

单 demo 文件不超过 300 行,优先用标准库。

## 与已有 demo 的边界

- **领域 demo 里同语言的实现**:聚焦在该知识点,**不展开**语言其他特性
- **本目录的 demo**:可以引用领域 demo,但核心目的是讲透**语言本身**

例如:
- `01-游戏开发/01-服务端/网络编程/IO多路复用/select/` 里的 `python/select_echo.py` 只讲怎么用 `selectors` 监听 fd
- `09-语言学习/Python/装饰器/` 讲的是 Python 函数是一等对象 + 闭包 + 语法糖,跟 IO 完全无关
